# 简历证据库 2.1

> **先看清自己真正会什么，再把它写成经得住追问的简历。**

这是一个面向中文求职者的开源简历助手。

它不只是帮你润色句子，也不会为了让简历显得厉害，就把“参与”写成“主导”、把个人练习项目写成真实上线成果。

它会先帮你梳理经历、发现稳定优势、判断能力掌握程度，再根据目标岗位生成真实、清晰、经得住面试追问的简历。

## 它能帮你解决什么问题

你可能遇到过这些情况：

- 做过很多事情，却不知道自己真正的优势是什么；
- 经历比较杂，不知道应该把自己定位成哪类人才；
- 借助人工智能工具做过项目，却不知道哪些成果真正算自己的能力；
- 简历写得很满，但面试官一追问就容易暴露边界；
- 想转行，却只能写“学习能力强、沟通能力强”；
- 同一份简历投递所有岗位，始终没有突出与岗位最相似的经历；
- 项目中的公司、客户、平台、模块和个人贡献写在一起，容易让人误解；
- 把公开数据、估算数据和真实内部结果混在了一起。

简历证据库会把这些问题拆开处理，而不是直接替你生成一份看起来很漂亮的简历。

## 完整工作过程

```text
具体经历
→ 深度访谈
→ 找到重复出现的稳定行为
→ 抽象成可以被工作证明的职业能力
→ 核对事实和证据
→ 判断能力掌握程度
→ 判断项目验证到了哪一步
→ 确定最适合的职业定位
→ 匹配目标岗位
→ 生成可防守的定制简历
→ 准备面试追问证据
```

## 不是简单的“性格分析”

“好奇心强、学习能力强、责任心强、沟通能力强”都可能是真的，但它们不能直接证明你适合某个岗位。

简历证据库会分三层判断：

### 第一层：自然倾向

例如：

- 容易注意到哪里不一致；
- 遇到复杂问题时喜欢先梳理结构；
- 习惯追问数据从哪里来；
- 做完事情后会主动检查有没有真正闭环。

这些只作为认识自己的线索，不会直接写进简历。

### 第二层：可以被工作证明的能力

自然倾向必须先转成可以观察的行为，再找到实际项目证据。

例如：

```text
“容易发现哪里不对”
→ 会主动比较数据来源、流程状态和预期结果
→ 能发现异常、不一致和遗漏
→ 找到真实工作或项目中的缺陷、对账、验收证据
```

到了这一层，才可能成为职业能力。

### 第三层：当前还不能包装的能力

如果只有愿望，没有项目证据；只有人工智能生成的结果，自己却解释不清；只有演示，没有真实用户验证，系统会明确标记为能力缺口，而不是继续强化表述。

## 判断你究竟掌握到什么程度

简历不能只看“做没做过”，还要看你真正掌握到了哪一步。

| 等级 | 掌握程度 | 可以怎样表达 |
|---|---|---|
| 0级 | 接触过、看过或参与过 | 写接触、了解或参与 |
| 1级 | 借助人工智能工具做出了结果，但解释和修改能力有限 | 写借助工具完成初版或原型 |
| 2级 | 能脱离资料解释核心流程、设计逻辑和关键决定 | 写清自己理解、定义或设计的范围 |
| 3级 | 能修改关键内容、定位问题并完成调试 | 写修改、调试和迭代经历 |
| 4级 | 能独立复现核心过程，并设计验证和失败处理 | 写独立复现或构建的真实范围 |
| 5级 | 在达到4级的基础上，经过真实用户、试点或生产环境验证 | 写真实验证过的对应范围 |

项目已经上线，不代表候选人自然达到5级；候选人能独立复现，也不代表项目已经产生真实业务价值。

## 人工智能辅助项目怎么判断

借助人工智能工具做出结果，不等于这个结果已经成为你的能力。

系统会继续检查你是否能够：

```text
解释清楚
→ 修改关键内容
→ 定位并解决问题
→ 不照着现成资料复现核心过程
→ 设计验证方法
```

对于重要项目，还需要回答：

- 为什么这样设计？
- 为什么没有选择其他方案？
- 核心数据是怎样流动的？
- 为什么需要智能体，而不是普通规则或固定流程？
- 哪些交给规则，哪些交给固定流程，哪些交给智能体，哪些必须由人确认？
- 成功的判断标准是什么？
- 失败或证据不足时怎么办？
- 核心调用过程是什么？
- 最主要的失败样例是什么？

如果这些问题解释不清，系统会提示：

> **先补项目解释权，不要继续强化简历表述。**

## 区分项目验证到了哪一步

个人项目和人工智能项目必须如实说明验证阶段：

```text
想法
→ 原型
→ 可运行演示或概念验证
→ 离线评测
→ 结构化用户访谈或专家评审
→ 小范围试点或真实用户使用
→ 生产环境运行
→ 已测量的业务结果
```

简历只能写到真实达到的阶段：

- 可运行演示不等于真实用户价值；
- 离线评测不等于生产效果；
- 进入生产环境不等于已经证明业务收益；
- 业务结果必须说明指标、统计范围、时间和个人贡献。

## 先做职业定位审计，再写母版简历

系统不会因为用户说“我想做某个岗位”，就直接把用户包装成那个岗位。

在生成母版简历前，它会先给出：

- 当前最强、最有证据的岗位定位；
- 次优但可以迁移的相邻定位；
- 当前不建议强行包装的定位；
- 最核心的垂直能力；
- 可以跨行业迁移的横向能力；
- 最大证据缺口；
- 下一步最值得补充的证明材料。

你可以决定未来想去哪里，但简历必须诚实反映你现在已经走到了哪里。

## 怎样选择要写进简历的内容

系统不会选择“听起来最厉害”的内容，而会优先选择：

> **和岗位高度相关、证据充分、本人掌握程度高、面试风险低的内容。**

每个重要表述都会检查：

- 事实由什么证据支持；
- 证据强不强；
- 本人真正负责了什么；
- 能否解释、修改和调试；
- 是否经过真实用户或生产环境验证；
- 面试官深入追问时有什么风险；
- 最稳妥、最准确的写法是什么。

与岗位高度相关，也不能掩盖证据不足。没有生产证据就不写生产成果，没有独立掌握就不写独立开发。

## 针对人工智能产品经理

内置的人工智能产品经理岗位知识重点关注：

- 复杂业务系统怎样引入人工智能；
- 普通规则、固定流程、智能体和人工确认之间怎样分工；
- 高风险流程怎样保留证据、责任和人工确认；
- 怎样处理异常、证据不足和决策支持；
- 怎样设计评测、失败样例和回归验证；
- 借助人工智能编程时，候选人真正掌握了多少；
- 项目是否经过真实用户、试点或生产环境验证；
- 候选人是否拥有项目解释权。

借助人工智能编程时，默认优先表达为：

> **借助人工智能完成产品构建、检查和验收的能力。**

只有具备更强的独立实现、复现和验证证据时，才使用独立开发类表述。

## 你最终会得到什么

- 一份事实和证据清单；
- 一份能力掌握程度清单；
- 一份职业能力库；
- 一份职业定位审计；
- 一份完整母版简历；
- 针对目标公司和岗位的定制简历；
- 重要简历表述的风险检查；
- 面试证据卡和追问准备；
- 当前不能包装的能力边界；
- 下一步补充证据的行动建议。

## 安装方法

在[最新发布页面](https://github.com/Charlotte57-zhou/jianli/releases/tag/v2.1.0)下载 `jianli-skill-v2.1.0.zip`。

解压后，把 `jianli` 文件夹放到：

```text
Windows：%USERPROFILE%\.codex\skills\jianli
苹果电脑或其他系统：~/.codex/skills/jianli
```

重新打开软件后，输入 `$jianli` 即可使用。

## 可以直接复制的提问方式

### 探索自己的优势和能力

```text
请使用 $jianli 对我进行深度访谈。一次只问我一个问题，从具体经历中识别稳定行为、职业能力、掌握程度和能力边界。先完成职业定位审计，不要直接写简历。
```

### 审计人工智能辅助项目

```text
请使用 $jianli 审计我的人工智能辅助项目。检查我能否解释、修改、调试、复现和验证，区分我的贡献与工具贡献，再给出安全的简历表述。
```

### 针对职位描述定制简历

```text
请使用 $jianli 分析这份职位描述。先检查岗位相关性、证据强度、本人掌握程度和面试风险，再从母版中生成可防守的定制简历。没有证据的关键词不要添加。
```

### 求职人工智能产品经理

```text
请使用 $jianli 和人工智能产品经理岗位知识，重点检查复杂业务流程、规则与智能体边界、评测与失败样例、项目解释权以及真实用户验证程度。
```

## 开源贡献边界

欢迎贡献新的岗位知识、匿名案例和能力映射，但请保持：

- 不写入候选人的真实姓名、电话、邮箱或雇主敏感信息；
- 不把个人经验描述成所有公司的统一招聘标准；
- 不把人工智能生成结果、可运行演示、离线评测或生产背景升级成更强的个人能力和业务结果；
- 不削弱“增强定位，但不增强事实”的核心原则。
