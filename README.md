# Jianli · 简历证据库

> **先核事实，再写简历。** 让 AI 少一点想象，多一点证据。

`jianli` 是为中文求职者设计的开源 Agent Skill。它不是“一键润色器”，而是一套从职业证据到岗位定制的完整工作流：

```text
原始经历 → 事实矩阵 → 职业证据库 → 母版 → JD 匹配 → 定制简历 → 面试证据卡
```

**一句话价值：允许增强定位，不允许增强事实。**

## 为什么值得用

普通 AI 简历工具常犯四类错误：

- 把“参与”写成“主导”，把 Demo 写成生产上线；
- 为了量化硬编百分比、ROI 或业务结果；
- 看见 JD 关键词就往简历里塞，却没有真实证据；
- 只改句子，不解决“什么该写、什么该前置、面试能否讲清楚”。

`jianli` 先建立证据边界，再做岗位匹配。你得到的不只是一份更顺眼的简历，而是一套可持续复用的求职资产。

## 你会得到什么

| 产出 | 解决的问题 |
|---|---|
| 事实矩阵 | 哪些能写、哪些要降级表述、哪些仍待确认 |
| 职业证据库 | 项目、指标、作品、能力和 bullet 不再散落 |
| 母版简历 | 保存完整、可辩护的事实源 |
| JD 证据矩阵 | 判断直接相似、相邻相似、可迁移与真实缺口 |
| 岗位定制简历 | 针对公司和岗位重新取舍，而不是堆关键词 |
| 面试证据卡 | 让简历上的核心主张经得住追问 |

## 它与“AI 润色简历”有什么不同

```text
AI 润色：原句 → 更漂亮的句子

Jianli：事实 → 证据 → 岗位判断 → 信息优先级 → 简历 → 面试
```

核心匹配顺序：

> **直接相似经历 > 相邻问题结构 > 有证据的可迁移能力 > 通用特质**

没有可靠 ROI，也可以诚实量化业务规模、场景数量、规则复杂度、项目周期、交付深度和验证强度。

## 30 秒开始

### 安装到 Codex

下载 Release 中的 `jianli-skill-v3.0.0.zip`，解压后将 `jianli` 文件夹放到：

```text
Windows: %USERPROFILE%\.codex\skills\jianli
macOS/Linux: ~/.codex/skills/jianli
```

重新打开 Codex 后即可使用 `$jianli`。

### 从源码安装

将仓库中的 `skill/jianli/` 复制到你的 Skills 目录，并保持文件夹名为 `jianli`。

## 直接复制这些提示词

### 1. 建立母版

```text
请使用 $jianli。先不要润色，根据我的原简历和项目资料建立事实矩阵、职业证据库和能力库，再生成一份母版简历。所有待确认信息单独列出，不要补写事实。
```

### 2. 针对 JD 定制

```text
请使用 $jianli 分析这份 JD。按“直接相似 > 相邻相似 > 可迁移能力”匹配我的证据，先给关键取舍，再生成公司和岗位专用简历。没有证据的关键词不要添加。
```

### 3. 评审别人的修改建议

```text
请使用 $jianli 评审这些简历建议。逐条判断：采纳、修改后采纳、不采纳或需要更多证据，并说明筛选价值、真实性、岗位匹配和面试风险。
```

### 4. AI 产品经理求职

```text
请使用 $jianli 和 AI 产品经理岗位包。先让 HR 看懂我解决了什么用户或业务问题，再保留 Agent、Tool Calling、Eval 等第二层技术证据，并区分原型、离线评测和生产结果。
```

## 为什么特别适合 AI 产品经理

首个内置 Role Pack 聚焦 AI 产品经理，覆盖：

- Agent / LLM / Workflow / Tool Calling / MCP；
- RAG、Human-in-the-loop、规则与模型边界；
- Agent Eval、离线证据与生产结果的区分；
- AI Coding 如何从“工具列表”写成真实交付能力；
- POC、Demo、GitHub 和作品链接怎么放更有利；
- 技术黑话如何翻译成 HR 能理解的产品价值。

表达顺序强调：

> **用户问题 → 产品判断 → 为什么用 AI → 个人决策 → 技术机制 → 评测与边界**

## 设计原则

1. **证据优先**：先确认动作、归属、口径和状态，再写文案。
2. **一份母版，多份定制**：母版保存事实，投递版服务具体 JD。
3. **可信量化**：规模、复杂度、交付和验证都可以量化，ROI 不是唯一答案。
4. **信息有优先级**：最相关的证据先被看见，版式服务筛选决策。
5. **简历即面试议程**：最醒目的五个主张，应该正是你最希望被追问的内容。

## 名称说明

项目名从 `evidence-first-resume` 缩短为 `jianli`：

- 中文用户一眼知道用途；
- `$jianli` 更短、更容易记；
- “证据优先”保留为核心主张和方法，而不是塞进名称。
