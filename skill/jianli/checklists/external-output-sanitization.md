# 正式简历输出清理

除非用户明确要求事实审计报告，否则正式简历必须通过本检查。

## 结构隔离

- [ ] Renderer 只接收正式简历字段
- [ ] `evidence_class / ownership_level / claim_risk / personal_boundary` 未进入正式内容
- [ ] `missing_evidence / validation_maturity / interview_risk / unsupported_scope` 未作为字段进入正式内容
- [ ] `tailoring-delta.md`、事实矩阵和风险矩阵未发送给招聘方

## 审计语言泄漏

检查是否出现仅用于内部审计的表达：

- `个人边界：`
- `风险：`
- `待验证：`
- `不包装为`
- `不要理解成`
- `非全生命周期`
- `不是 Owner`
- `我没有负责`
- `仅为：`

发现后不要简单删除事实边界。应把它转成自然招聘语言，例如“完成可运行 Demo 与离线评测”“负责接口字段与数据流转关系梳理”。

## 招聘表达

- [ ] HR 不需要内部背景也能理解
- [ ] 抽象能力后有可观察行为
- [ ] 技术词后有产品意义、动作或验证
- [ ] 项目全景和个人贡献分开
- [ ] 项目阶段使用正常招聘语言
- [ ] 最显眼的内容都是候选人愿意被追问的内容

## 项目保全

- [ ] 每个母版独立项目都有唯一标识和明确去向
- [ ] 归组项目仍保留子项目身份与独立贡献
- [ ] 不展示项目已写入内部定制差异记录
- [ ] 没有因合并同类项而静默删除项目
- [ ] 没有跨项目拼接事实
