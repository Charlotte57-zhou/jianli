# v3.1.0 匿名验收场景

## Case 1：普通产品经理简历

- 输入：普通工作经历和目标 JD；
- 期望：先核事实，再匹配 JD，通过招聘表达卡生成自然要点；
- 禁止：直接从原文润色并添加没有证据的结果。

## Case 2：大型项目中的局部贡献

- 输入：大型平台规模与候选人负责的部分模块；
- 期望：项目全景提供上下文，个人职责使用准确动词；
- 禁止：把平台规模变成个人完整所有权。

## Case 3：AI Coding 个人项目

- 输入：AI 生成实现、候选人能够解释和修改但没有真实用户；
- 期望：记录相应所有权，写 Demo / 离线验证阶段；
- 禁止：自动写成独立全栈开发或生产价值。

## Case 4：AIPM JD

- 输入：包含 Agent、MCP、Eval 的 JD；
- 期望：先讲业务问题、为什么使用 AI、AI 边界、人工控制和验证，再用技术词证明；
- 禁止：第一句话堆叠技术缩写。

## Case 5：内部审计语言过滤

- 内部：不是完整项目 Owner、未上线、缺乏生产验证；
- 外部：准确描述负责范围，以及真实达到的 Demo 或离线评测阶段；
- 禁止：内部审计原句进入正式简历。

## Case 6：没有证件照

- 输入：用户没有要求照片；
- 期望：两个内置 Renderer 均不出现空照片框。

## Case 7：内容超过一页

- 输入：匿名的多段工作和项目经历；
- 期望：保持正常字号并自然扩展为两页；
- 禁止：删除独立项目或用极小字号塞进一页。

## Case 8：合并同类项目

- 输入：三个属于同一平台、问题相近但贡献和证据独立的项目；
- 期望：可以归组，但三个子项目仍可识别；不展示时在定制差异记录中说明；
- 禁止：因合并同类项让任一项目静默消失，或跨项目拼接指标。
