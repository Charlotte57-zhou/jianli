# Master Resume vs Tailored Resume

## Core idea

Do not try to make one resume perfectly serve every job.

Use a two-layer system:

1. **Master Resume / Career Evidence Base**
   - complete, evidence-backed, reusable;
   - stores all defensible projects, bullets, metrics, tools, domains, and links;
   - optimized for truth and coverage, not for sending.

2. **Tailored Resume**
   - created for a specific company + role + JD;
   - selects and reorders evidence from the master;
   - mirrors relevant market language where truthful;
   - removes low-relevance detail;
   - becomes the version actually submitted.

The master is the source of truth. Tailored resumes are views over that source.

## Why a single universal resume underperforms

Hiring is usually a fast similarity judgment:

> “Has this person solved a problem sufficiently similar to ours, and can they become productive quickly?”

A universal resume often spreads attention across too many domains. A tailored resume raises the signal-to-noise ratio.

## Tailoring hierarchy

When selecting evidence for a JD, prioritize:

### Level A — Direct similarity

Same or very similar:

- user type;
- business scenario;
- product type;
- workflow;
- technical mechanism;
- business model;
- delivery environment.

Example:

A candidate who has built an enterprise exception-handling Agent should foreground that when applying to an enterprise Agent product role.

### Level B — Adjacent similarity

Not the same domain, but highly similar problem structure.

Examples:

- electricity settlement → financial reconciliation;
- cross-system master-data inconsistency → enterprise data-governance workflow;
- rule + Agent exception handling → compliance / operations / support investigation.

### Level C — Transferable capability

The domain differs, but the underlying capability is proven.

Examples:

- complex workflow decomposition;
- rule modeling;
- cross-system interface/data mapping;
- B2B stakeholder alignment;
- human-in-the-loop AI design;
- eval/test-driven AI product delivery.

### Level D — Generic claims

Examples:

- strong communication;
- fast learner;
- responsible;
- good teamwork.

These have little value unless supported by evidence. Do not use them as the main bridge.

## Tailoring does not mean rewriting facts

Allowed:

- reorder projects;
- reorder bullets;
- shorten irrelevant content;
- choose a more relevant project title if still accurate;
- mirror JD terminology when equivalent;
- emphasize direct/adjacent evidence;
- add a truthful transferability bridge;
- change the target-role label;
- change which links are visible.

Not allowed:

- upgrade participation to ownership;
- add technologies merely because the JD mentions them;
- invent production usage;
- invent metrics;
- rename a project so aggressively that it becomes a different project;
- claim domain expertise that is only an analogy.

## Tailored resume as an interview agenda

Every highlighted bullet increases the probability that the interviewer will ask about it.

Therefore, tailoring should optimize not only for screening, but for:

> “If they ask me about the top 5 things on this resume, are those the 5 topics I most want to discuss?”

If not, reorder again.

## Recommended outputs

For each target JD, produce:

1. Tailored resume.
2. Tailoring delta note — what changed vs master and why.
3. JD evidence matrix.
4. Interview evidence cards for the top 3–5 claims.

The delta note is internal and should not be sent to recruiters.
