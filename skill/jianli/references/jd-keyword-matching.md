# JD Keyword Matching

## Goal

Optimize for real hiring language without turning the resume into ATS keyword spam.

## The only safe formula

> High-frequency JD keyword ∩ candidate evidence = usable resume keyword.

## Workflow

1. Collect 10–20 JDs the candidate would genuinely apply to.
2. Normalize synonymous terms.
3. Count frequency.
4. Separate:
   - must-have;
   - common;
   - differentiator;
   - noise.
5. Map each term to candidate evidence.
6. Decide placement:
   - first screen;
   - work/project bullet;
   - skills;
   - omit.

## Example for AI Product Manager

Potential JD terms:

- AI Agent
- LLM
- RAG
- workflow
- Tool Calling / Function Calling
- Prompt
- Eval
- POC / Demo
- AI Coding
- product planning
- PRD / prototype
- B2B
- 0→1
- cross-functional collaboration
- data / metrics

Do **not** add RAG merely because it is common. If the candidate’s projects did not use RAG, omit it.

## Keyword placement

### First-screen keywords

Only the few terms that define the candidate:

- AI Product Manager
- B2B / enterprise
- Agent
- AI Coding
- 0→1

### Project keywords

Terms supported by concrete evidence:

- Agent Eval
- Human-in-the-loop
- Tool Calling
- workflow
- interface mapping
- rule engine / rules
- POC / Demo

### Skill-only keywords

Tools or technologies that are real but secondary.

## JD matching is not identity replacement

A candidate with strong complex enterprise product experience should not erase that background to look like a pure “LLM PM.”

The differentiator may be the combination:

> complex enterprise domain + AI product capability.
