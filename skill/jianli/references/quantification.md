# Credible Quantification

## Why quantification matters

Recruiters use numbers as compression. A number can quickly answer:

- how large;
- how complex;
- how deep;
- how complete.

But a bad number destroys trust.

## Four useful number types

### 1. Scale

Examples:

- 26 regions
- 3 million records/month
- 6 million documents/month
- 12 systems
- 40 interfaces

### 2. Complexity

Examples:

- 33 exception classes
- 4 evidence domains
- 5 states
- 17 visa categories × 35 fields

### 3. Delivery

Examples:

- 4 months on-site
- 3 releases
- 5 modules
- 2 client programs

### 4. Quality / verification

Examples:

- 330 unique automated tests
- 37 frozen eval samples
- zero-model PASS path
- bad-case review mechanism

## Outcome metrics

Time reduction, cost reduction, accuracy, conversion, and revenue are powerful only when:

- measured;
- attributable;
- reproducible;
- not reverse-engineered from assumptions.

## Do not force every bullet to have a number

A resume with invented precision is worse than a resume with fewer but defensible metrics.

## Quantification test

Before using any number, ask:

1. What exactly is being counted?
2. Is this internal, public, or estimated?
3. Does the number belong to my module?
4. Can I explain its source in an interview?
5. Does it measure scale or outcome?
6. If outcome: was it actually measured?
